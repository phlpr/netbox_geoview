# Device-role marker validation — 2026-10-22

This validates the development checkout's optional NetBox role colors and
per-role marker overrides. It is separate from the device-role filter change
and does not change the published version or supported NetBox range.

## Behavior

- `use_role_colors` defaults to `False`. Only the Boolean `True` enables
  automatic colors from NetBox's assigned DeviceRole.
- With the switch off and no per-role override, existing site-group/default
  marker styles continue to apply to devices. Site markers are unaffected.
- `device_role_markers` overrides color, symbol, image URL, size and anchors.
  These overrides work with either switch value and take precedence over the
  automatic role color. Partial overrides retain other inherited style fields.
- Role ID keys take precedence over slug keys, then name keys. Matching is
  case-insensitive; numeric IDs disambiguate repeated names/slugs in role trees.
- A role override applies only to that assigned role. Child roles use their own
  role color and configuration. Empty `icon_url` clears an inherited image.
- Custom images use their own colors. NetBox colors apply to the built-in pin.
- Full maps and widgets use the same shared style helper. The existing query
  preloads roles and site groups; calculating marker styles adds no queries.

The integration cases cover strict Boolean handling (strings do not enable
colors), backwards-compatible defaults, site/device separation, explicit color
priority, case-insensitive ID/slug/name matching, custom image dimensions and
anchor points, clearing inherited images, independent child-role styles,
malformed legacy colors, invalid override containers, widget parity and a
zero-additional-queries assertion for preloaded devices.

Browser checks compare actual pin CSS colors and symbols with all 17 local
devices' role/configuration values, verify that site pins remain unchanged and
create a native dashboard widget with identical marker styles. An isolated DOM
probe renders configuration generated by the actual backend under temporary
settings: a role-specific image with explicit size/anchors and a pin with an
explicit color and symbol. The image uses the existing bundled Leaflet PNG.
The probe's settings are not written to the local instance configuration.

The running local NetBox has `use_role_colors=True` and role-specific letter
symbols for manual review. The existing symbol CSS rotation was corrected so
letters remain upright; the full-map/widget asset versions were advanced to
reload that CSS. The browser checks assert upright symbol transforms, and
desktop screenshots were inspected. A follow-up centering check removed a
3.36-pixel upward offset: all 17 letter boxes now share the circular pin head's
center at 1440-pixel desktop and 428-pixel mobile viewport widths. Enlarged
marker screenshots were inspected, and map/widget asset versions were advanced
again so existing browsers load the correction. Browser
authentication uses a disposable account and a temporary session; the session
and account/filter/dashboard records are removed after the checks. Artifacts
are under `/home/prohph/.local/share/netbox-geoview/issue-4/`.

Tests use the dedicated databases and version-specific environments described
